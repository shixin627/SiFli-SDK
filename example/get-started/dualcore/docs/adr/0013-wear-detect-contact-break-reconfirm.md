# 0013 — 配戴偵測:接觸中斷後暫停 DC-held,要求脈搏重確認

日期:2026-06-10
狀態:Accepted
前置:ADR 0012(OFF→ON 滑動窗投票)
相關檔案:`src/modules/algorithm/WearDetect/wear_detect.c`

## 問題

ADR 0012 修好「戴著卡未配戴」後,實機驗證(2026-06-10 14:58~15:00,
COM9)同時暴露反向缺陷:**摘錶放桌上後永久卡「已配戴」**。

實測票流:
- 14:59:14 摘錶瞬間 DC=37435 崩落,投出 1 票 OFF(翻 OFF 需連續 3 票
  ≈ 4.5 秒),但使用者 ~1.5 秒內就把錶放上桌面。
- 桌面 DC = 46,880~46,930,**比手腕(46,200)還高** — DC 完全無法分辨
  這張桌子和皮膚。
- WEARING 狀態的維持規則是 DC-held(只看 DC、刻意不看 PI,為了保護
  睡眠中弱脈搏不掉線 — 歷史 root cause A1)→ 桌面被當成手腕,卡 ON。
- 桌面 PI = 0.00032~0.00055,超平、無脈搏特徵(對照:OFF→ON 的脈搏
  閘要求 PI ≥ 0.0010,桌面永遠過不了)。
- 下游影響:sleep service 在桌上開始跑(14:59:22)、bg_hr 對桌面空燒
  LED。

此為**既有缺陷**:ON→OFF 路徑在 ADR 0012 中一行未動;以前因為 ON
幾乎不可達所以觀察不到。

## 決策

引入「接觸中斷重確認」(contact-break re-confirmation):

1. **觸發**:WEARING 中 DC 崩落(< 42000)**且**當下 IMU 變異數
   ≥ `IMU_VARIANCE_THD`(0.03)→ `contact_break_pending = true`。
   摘錶的特徵就是「DC 崩 + 動作」;睡眠中無動作的 DC 微跌
   **不觸發**,DC-held 照舊 → A1 保護不變。
2. **重確認**:pending 期間 DC 回到接觸區不再直接 DC-held,改走既有
   的 live-pulse 投票閘(PI ≥ 0.0010 + range 檢查),票進 ADR 0012
   的 8 評估滑動窗;窗內 ≥ 3 票 → 解除 pending、恢復 DC-held,
   **狀態全程不掉**(錶帶鬆動場景無感)。
3. **逾期**:倒數 `RECONFIRM_LIVE_EVALS = 60` 個「**可用評估**」後仍
   未確認 → 每次評估投 OFF → 連 3 票翻未配戴。
   **倒數只在「PPG 有新資料且手腕靜止」的評估扣**:
   - PPG stale / settle(bg_hr duty-cycle 斷電期:睡眠 60s 開/120s 關,
     醒著每 ~15 分鐘 40s)→ **凍結**。若用牆鐘寬限,翻身落在 burst
     尾段時寬限會在斷電期燒完,下個 burst 開頭即使脈搏完美也必翻
     OFF — 此缺陷由 adversarial review 抓出(blocker),故棄用牆鐘。
   - 動作中(IMU 變異 ≥ 0.03)→ **凍結**。運動偽影本來就過不了脈搏
     閘,牆鐘會把「運動中錶帶鬆」餓死成誤 OFF;且會動的表面不是桌子。
   - 語意:**感測器有 60 次乾淨機會看脈搏、一次都沒看到 = 不是手腕**。
4. 任何狀態轉換(`set_status`)清 pending;arm 時先寫倒數值再立 flag
   (無鎖讀者不會看到 flag=true 配舊倒數)。

## 翻 OFF 的時間特性(桌面案例)

- 測試台(接充電線,PPG 連續供電):60 次評估 ≈ 90~120 秒翻 OFF。
- 電池 + 睡眠 cadence:約 2 個 burst ≈ 5 分鐘。
- 電池 + 醒著閒置(15 分鐘/burst):最壞 ~3 個 burst ≈ 30–45 分鐘。
  代價只是幾個 40 秒的 LED burst 與延遲的旗標,相比睡眠誤掉線是
  數量級更輕的失效(review 結論)。

## 已知殘餘風險(權衡後接受,待實機資料)

1. **深睡極弱灌流**:翻身觸發重確認後,若 PI 過門檻率遠低於清醒實測
   的 ~30%,60 次可用評估內湊不到 3-of-8 → 誤翻 OFF,需下次翻身開
   probe 回 ON。收一夜深睡資料後再決定是否放寬 pending 路徑的
   pi_range 條件(不動 OFF→ON)。
2. **輕放偽重確認**:緩慢輕放使偽影 PI 落在 0.001~0.1、range < 0.15,
   理論上可在落桌混合期湊出 3 票偽確認、重鎖 ON(本次 log 安全是因
   0.40 巨值同窗撐爆 range)。margin 僅 1 票,待「輕放」實測驗證。
3. **IMU 門檻 0.03 對摘錶無鑑別力**(翻身/抓癢都過):arm log 現在會
   記錄實際變異數,收集摘錶 vs 翻身的量級後再考慮調高(~0.3)。
   注意 arm 不可改成連續 2 票 DC 崩 — 實測摘錶空中只有 ~1.5s。

## 驗證

- 實機票流回放(摘錶→桌面):pending 於 14:59:14 觸發,桌面票數 0,
  90s 逾期 → OFF。
- 三路 adversarial review(狀態機/睡眠迴歸/嵌入式併發)。

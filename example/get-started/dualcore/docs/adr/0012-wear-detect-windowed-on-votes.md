# 0012 — 配戴偵測 OFF→ON 改為滑動窗投票(取代連續 3 票)

日期:2026-06-10
狀態:Accepted
相關檔案:`src/modules/algorithm/WearDetect/wear_detect.c`

## 問題

使用者回報:心率很容易顯示「未配戴」之後就沒有心率(手機端心率曲線大缺口)。

實機 log(2026-06-10,COM9 LCPU + COM10 HCPU)定位出根因:

- DC 接觸值健康(45.9k~46.3k,遠高於 42000 門檻),**不是**接觸偵測問題。
- 配戴中的手腕 PI 在 0.0005~0.00144 之間徘徊(當時接著充電線,充電雜訊
  會壓低訊號品質),只有約 30% 的評估能過 `PI_THD_TO_ON = 0.0010`。
- 舊規則要求 **連續 3 次**評估(每 1.5s)都過門檻才翻 ON,且任何一次
  hold 會把計數器扣回去。30% 命中率下連續 3 次的機率約 2.4%/次評估。
- 實測 1 分鐘投票序列最長連續只有 2 票;HCPU log 顯示開機後卡
  「未配戴」整整 23 分鐘,直到抬腕壓緊感測器才翻 ON。
- 期間 `bg_hr_skip_reason()` 全部回 `BGHR_NOT_WORN` → 心率曲線缺口。
- 加重因素:PPG 資料每 ~10.5s 斷流一次(>5s 無樣本觸發 stale 評估,
  與充電 10s 電壓輪詢同節奏;`PPG_RACE_DEBUG` 另案追蹤中),每次 stale
  評估投 hold,進一步打斷「連續」。

## 決策

OFF→ON 的遲滯從「連續 3 票」改為「**最近 8 次評估(~12s)內累積 3 票**」:

- `ctx.on_counter`(int8_t 連續計數)→ `ctx.on_vote_window`
  (uint8_t bitmask,每次評估左移,vote ON 填 1)。
- 翻 ON 條件:窗內 ON 票數 ≥ `HYSTERESIS_ON`(3)。
- vote OFF(DC 崩落)清空窗;PPG 關閉/清緩衝的三個點(probe 過期 ×2、
  settle 完成)同步清窗,舊票不跨 session 殘留。
- ON→OFF 側(`off_counter`,連續 3 次 DC < 42000)**完全不動**——
  DC 崩落票是確定性的,連續語意在該方向是對的。
- 所有 per-vote 品質閘不動:`PI_THD_TO_ON`、`PI_RANGE_MAX` 運動偽影
  拒絕、PI 變異性檢查、settle 期忽略。

## 為什麼誤判防護不變

桌面/充電座雜訊的 PI 實測最高 ~0.0008(見 code 內註解的量測記錄),
**過不了 0.0010 門檻,根本投不出 ON 票**。擋住桌面的從來不是「連續 3」
而是 PI 門檻本身;滑動窗只改變「真脈搏間歇過門檻」時票的累積方式。
放下手錶的運動偽影(PI range ~0.27)仍被 `PI_RANGE_MAX = 0.15` 拒絕。

## 驗證

- 用實測投票序列回放:舊邏輯整段 log 翻不了 ON;新邏輯在第 21 秒翻 ON
  (窗內 38.4s/44.5s/45.9s 三票)。
- 翻 ON 後即 DC-held,行為與原設計一致。

## 後續(本 ADR 不處理)

2. 2026-06-10 log 中兩次無 panic dump 的重開機(13:13:05、13:39:48,
   前各有 60s/38s 靜默)— 待重現。
3. `PI_THD_TO_ON = 0.0010` 對弱灌流手腕仍偏緊;若窗化後仍有體質性
